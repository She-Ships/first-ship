## Before you start

1. Open the original issue and confirm it is still available.
2. Check recent comments, assignees, and linked pull requests.
3. Read the project's `CONTRIBUTING.md` or contributor guide.
4. If the project asks contributors to claim work first, comment before coding.
5. Keep your pull request focused on the issue.
6. Run the project's documented checks.
7. Link the issue in your pull request and respond to maintainer feedback.

> Your first PR does **not** need to be impressive. The goal is to learn the workflow, communicate well, and get something genuinely useful merged.
